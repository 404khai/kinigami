# Replay Take 84

The archive is self-contained. Use Linux x86-64 with Python 3.10.12 and the three locked packages in requirements84.txt, taskset, and a C++17 compiler (no special library). The canonical run uses a single available CPU per Python process, BLAS single-thread mode, and a fixed hash seed. Run from an extracted copy:

    sha256sum -c SHA256SUMS
    ./replay84.sh
    sha256sum -c SHA256SUMS

For an independent clean replay, copy only *.py, tube84.cpp, replay84.sh, requirements84.txt, catalog-reserves79.json, upstream80.json and routes84.json to an empty directory. Run ./replay84.sh there, then byte-compare each of the 11 generated JSON files to the archive. No execution of the Kin simulator, Gate or solver is part of this study. No network or repository checkout is needed to replay. Different numerical/library builds can change facet order/last digits.

Inputs: head82.py and drive82.py are the inherited Take 82 geometry primitives and catalog reservations. head84.py defines the coordinated, modified interface; body84.py defines the actual installed reservations and transforms. routes84.json is explicit frozen manufactured-link geometry, not motion generated by a live planner. The sampled overlap ledger intentionally includes attachments, clearance reservations, and tooth/thread sweeps; no whitelist hides contacts. All lengths mm, forces N, moments N·mm, volumes mm³. Positive X is the coupling direction. Angles about X start at +Y toward +Z; yaw rotates about global Z through (−30,3.05,0).
